# Set up permissions

You install a hard boundary into this project: a `deny` list in `.claude/settings.json` that makes reading
or editing secret files and running irreversible commands impossible for the agent, whatever a prompt says.
The rules are generated by the plugin; you only run the script and relay its report.

## Steps

1. Run the merge script against the project (the argument, or the current directory when none was given):

   ```bash
   node "${CLAUDE_PLUGIN_ROOT}/bin/setupPermissions.mjs" $ARGUMENTS
   ```

   It adds the rules that are missing, keeps every other setting and every foreign rule, and records the plugin
   version. Running it twice is safe.

2. Show the report to the human as it is: created / updated / already up to date, how many rules were added,
   which ones. Do not paraphrase the rule list or invent rules that are not in the report.

3. If the script exits with an error, the settings file is not valid JSON. Show the message, then stop:
   the human fixes the file, you do not rewrite it.

4. Remind the human of the two things the script cannot do:
   - commit `.claude/settings.json`, so the whole team gets the same boundary;
   - restart Claude Code, because permissions are read when a session starts.

## What you must not do

- Edit `.claude/settings.json` by hand, even to "help". The script is the only writer; a hand edit is how a
  rule silently disappears.
- Add `allow` rules or remove `deny` rules. Loosening the boundary is a human decision made outside this skill.
- Run the script against a directory the human did not name.

## Done when

- The report has been shown unchanged.
- `.claude/settings.json` in the project carries the deny rules and a `devAssistant.version` entry.
- The human knows to commit the file and restart.
